# MeasureGH V3 — consolidated review checklist

Use this after the GitHub Pages deployment. The purpose is one consolidated product review before freezing the P1C-B1 production schema.

## 1. Navigation and catalogue

- Does “Ways to measure” make the five approaches intuitive?
- Does the default Browse page feel like a public catalogue rather than a backend register?
- Is hiding nested variants/components by default correct?
- Are family links understandable?
- Are the evidence-pending records useful or distracting at this stage?

## 2. Instrument / family stress tests

Check GHSI-10, PGSI, PHQ-9 and IGT.

- Is the family/form distinction obvious?
- Are constructs separated from evidence quality?
- Does the evidence line make sense without specialist explanation?
- Do tasks such as IGT feel different enough from questionnaires?

## 3. Assessment stress tests

Check DSM-5, NICE assessment, DIGS and WMH-CIDI.

- Do editions/releases/frameworks read correctly?
- Does NICE avoid looking like a psychometric scale?
- Are implementation resources separated from empirical applications?

## 4. Methods stress tests

Check G-TLFB, PAF/cost estimation, VAS, GAMTOMS and SNA.

- Do the “What needs to be specified?” blocks make methodological differences understandable?
- Are estimand/output distinctions clear?
- Does configuration avoid becoming construct proliferation?

## 5. Indicator stress tests

Check net loss, merchant outflow, treatment dropout, IMD and QALY.

- Are numerator/denominator/accounting/window/geography assumptions visible enough?
- Are loss, harm, affordability and disorder kept distinct?
- Is QALY clearly distinct from utility instruments?

## 6. Qualitative stress tests

Check MSC, GMB and life-course social-cost case study.

- Does MSC read as a method with a recovery application rather than a standardised gambling protocol?
- Does GMB distinguish shared causal hypotheses from verified causation?
- Does the case-study page separate narrative, observed resource use and modelled/monetised costs?

## 7. Cross-product tools

- Compare: are the rows genuinely useful across very different object types?
- Help Me Choose: do the filters narrow without implying recommendation/ranking?
- Constructs: does construct-first navigation help users find relevant approaches?

## 8. Evidence presentation

- Is “Evidence currently identified” factual and understandable?
- Are detailed findings useful, or too technical for the default page?
- Are applications, methodological evidence and implementation resources clearly different?
- Are evidence gaps prominent without sounding like definitive absence claims?

## 9. Final schema-freeze decisions

After reviewing the site, consolidate issues into one pass:

1. fields to add to production schema;
2. fields to remove or keep backend-only;
3. public labels to change;
4. family/public-entity changes;
5. Compare/chooser field changes;
6. detail-page archetype changes;
7. final P1C-B production protocol changes.

Then freeze and start P1C-B1.
